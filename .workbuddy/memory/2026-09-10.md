## Rhine Lab 三维首页移植到 magic-resume 后的卡死排查

- 结构：`D:\my-blog\RhineLabUI` 是原始独立项目；`magic-resume/src/rhine/*` 是移植副本，
  由 `src/components/portal/RhinePortal.tsx` 懒加载挂载，`src/routes/$locale.tsx` 用它替代旧营销首页。
  移植时移除了 audio / pwa / startup / fonts.css（合理），其余逻辑与原文逐行一致。

- 卡死根因（未修复，等用户确认）：
  1. `src/rhine/main.ts:286` 的 `#file-ticks` 只在挂载时按初始列生成一次（2 个按钮），
     而 `data.ts` 移植后 5 列模板数变成 2/1/2/2/2（「时间轴」列只有 T-004 一个）。
  2. `updateSelection()`（main.ts:392）用固定长度的 fileTicks 索引当前列 files，
     进入「时间轴」列时 `files[1]` 为 undefined → `records[undefined].id` 抛 TypeError。
  3. 拖动/惯性路径 `navigatePlane → onSelect → select()` 运行在 `frame()` 的 rAF 回调里，
     而 `frame()`（main.ts:903）无 try/catch 且 rAF 续帧写在最后一行 → 抛错后渲染循环永久断链。
  4. 单阵列还会让 `stepFile()` 的 `files.length < 2` 提前返回，滚轮表现为「滚了没反应」。

- 原版无此问题：DESIGN.md 约束每列固定 8 份档案，fileTicks 恒为 8。移植到模板库时该前提被破坏。

- 修复方案（待用户选择）：A 按当前列重建刻度并加空值保护；B 重新分组模板使每列 ≥2；
  C frame() 加 try/catch + finally 续帧兜底；D 单阵列时滚轮回退为切列。推荐 A+C。
